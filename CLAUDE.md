# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the dev server (Next.js, default port 3000)
- `npm run build` — production build
- `npm run start` — run the production build
- `npm run lint` — ESLint (flat config via `eslint.config.mjs`, `eslint-config-next`)

There is no test suite configured in this repo (no test script, no test runner dependency).

## Architecture

Next.js 16 App Router project (mixed JS/TSX: `app/layout.tsx` is TypeScript, all pages and API routes are plain `.js`). Tailwind CSS v4 for styling, `recharts` for charts. No database — all data is either fetched live from external APIs or persisted client-side in `localStorage`.

**`next.config.mjs` disables build-time checks**: `eslint.ignoreDuringBuilds` and `typescript.ignoreBuildErrors` are both `true`. TypeScript `strict` is on in `tsconfig.json`, but type/lint errors will not fail `npm run build` — don't assume a clean build means the code type-checks or lints cleanly.

`app/error.js` is a root error boundary (client component) that catches unhandled render errors anywhere under `app/` and shows a message + reset button instead of a blank page. Client components that fetch from the API routes below (`NewsCard`/`StockTicker` in particular) also defensively check `Array.isArray(data)` before using the response, since a non-2xx/error-shaped JSON response would otherwise crash the component.

### Routes

- `/` (`app/page.tsx`) — main dashboard: `QuickLinksSection` (a static black "바로가기" bar of external links — market data tools plus 5 overseas-stock news sites; the 2 most-used sites are always visible, the other 3 are behind a local `showMore` toggle, all just hardcoded `<a target="_blank">` links with no fetching), live stock/macro ticker (`StockTicker`) + category news cards (`NewsCard`), both client components that poll the API routes below on mount.
- `/archive` (`app/archive/page.js`) — "ETF 포트폴리오 빌더" (portfolio builder). A single large client component (~800+ lines) with five tabs (내 자산 / 모델 포트폴리오 / 보유 비중 / 수익률 및 배당 / 리밸런싱), all derived state (portfolio weights, sector/size/style exposure, CAGR-weighted backtest projection) computed inline on every render from `masterPool` (fetched) + `tabLists`/`quantities` (local state). The 리밸런싱 tab also lazily fetches `/api/sector-performance` (only once, when that tab is first opened). The 내 자산/모델 포트폴리오 search box isn't limited to the ~90 hardcoded `masterPool` ETFs: typing a ticker with no match shows a "티커로 직접 추가" row (`handleAddCustomTicker`) that appends it to `customTickers` (persisted to `localStorage` under `kijay_custom_etfs`) and refetches `/api/etfs?extra=SYMBOL1,SYMBOL2` via `fetchMasterPool()`. Custom tickers get live price, live sector weightings (when Yahoo has them), live dividend yield, and live 1y/3y/5y/10y CAGR — but no sizes/styles data (no free reliable source for that), so `xray.sizes`/`xray.styles` are left as `{}`, meaning custom holdings are automatically excluded from the 대형/중형/소형 and 가치/혼합/성장 breakdown charts (`getPercentage()` divides by total portfolio value, same as how existing bond/gold entries like `TLT`/`GLD` — which also have empty `sizes`/`styles` — already behave) while still counting fully toward sector exposure, dividend income, and CAGR-based backtest projections.
- `/infinite` (`app/infinite/page.js`) — thin wrapper that embeds an external site (`https://fire-gate.app/`) in a full-screen iframe.
- `/journal` (`app/journal/page.js`) — three tabs: 매매일지 (trade journal: stock name (optional), ticker symbol (required), buy date, buy price, quantity, free-text rationale per entry; persisted to `localStorage` under `kijay_trade_journal`, so private to whichever browser/device created it), 종목 진단 (10-item fundamentals checklist + a Benjamin Graham fair-value calculator, moved here from `/archive`; this tab's state — checkbox states, Graham calculator inputs — is not persisted, it resets on reload, matching its original behavior on `/archive`), and 주간데이터 (see below). Entries created before the stock-name/ticker split used a single combined `ticker` field (e.g. `"엔비디아(NVDA)"`); `migrateEntry()` in `app/journal/page.js` converts those on load by extracting a ticker from trailing parentheses, leaving `symbol` blank (and price/return showing `-`) when it can't. The journal fetches live current prices for every unique `symbol` in the list from `/api/journal-quotes` (no caching — real-time, refetched whenever the entry list changes or the user clicks "시세 새로고침") and shows the return vs. `buyPrice` per entry. It also has "📋 표로 복사" (copies the currently-filtered list as tab-separated text via `copyTextToClipboard()`, pasteable straight into Google Sheets/Excel — falls back to a hidden-textarea `execCommand('copy')` when `navigator.clipboard` is unavailable, e.g. non-HTTPS) and "다른 기기로 옮기기" (export encodes all entries as JSON → UTF-8 bytes → base64 via `encodeToCode()`; import reverses that and merges by `id`, skipping entries whose `id` already exists so re-importing is idempotent and never overwrites existing data). The 주간데이터 tab lazily fetches `/api/weekly-data` (only once, when that tab is first opened) and renders four tables (`WeeklyDataTable`, shared component defined at the bottom of the file): 월300 투자 공식 (10 KRX-listed Korean ETFs tracking US indices, e.g. ACE/TIGER/KODEX/SOL products — priced in KRW, rendered with `priceDecimals={0}`), 주요 지수 (9 US indices/ETF proxies), 주요 섹터 (the same 11 GICS SPDR ETFs as `/archive`'s rebalancing tab), and S&P500 상위 기업 (15 large-cap names) — each row shows 기준가, 52주 고점 대비 하락률, 주중/월중/1M/3M/6M/12M % change, computed server-side from daily `yahoo-finance2` `chart()` history.

`app/page.tsx`'s `StockTicker` `renderItem` supports optional `item.primaryLabel` / `item.secondaryLabel` badge text on any item from `/api/stocks` (the second one defaults to `'현'` when `item.spotChange` is set but no `secondaryLabel` is given, preserving old behavior). No current `/api/stocks` entries set these — it's dormant capability for a future metric that needs a custom badge (e.g. "MoM", "발표대비") instead of a plain % change.

### API routes (`app/api/*/route.js`)

These are server-side data-fetching proxies with no persistence layer; price data uses `cache: 'no-store'` and spoofs a browser `User-Agent` when calling external services. Two routes (`api/etfs`'s sector weightings, `api/sector-performance`) deliberately deviate from the no-cache pattern — see below.

- `api/news` — for `query === '해외증시'`, calls undocumented internal `stock.naver.com` APIs instead of the Naver Search API: first `/api/foreign/news/worldNews` (해외뉴스 list), then `/api/domestic/news/focus?sid=403` (the "뉴스포커스 > 해외증시" tab's own API, kept as a secondary candidate since it's occasionally empty) — both queried with a `date` computed in KST (`todayKstYyyyMMdd()`), not server-local time, since Vercel runs in UTC and a naive `new Date()` can be off by a day near midnight KST. `extractNewsList()` parses the response defensively (tries several key names for the array wrapper/title/link) since these are reverse-engineered, undocumented endpoints Naver can change without notice. If both candidates fail or return empty, this category returns an explicit 502 `{error}` rather than falling back to the generic Naver Search API keyword search — a keyword search for the literal term "해외증시" tends to surface unrelated domestic articles that merely mention the phrase, which was worse (looked like success but was wrong) than a visible error. (This replaced an older approach that scraped `finance.naver.com`'s HTML news list directly with `cheerio`/`iconv-lite`; Naver's `stock.naver.com` redesign stopped serving the same curated feed at that old URL, and the `cheerio`/`iconv-lite` deps are no longer used by this route.) All other categories go straight to the Naver Search News API. Naver API credentials are read from `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET` env vars (see `.env.example`); the route returns a 500 with a clear message if they're unset.
- `api/stocks` (`dynamic = 'force-dynamic'`) — pulls a fixed list of indices/ETFs/macro tickers from Yahoo Finance's undocumented chart endpoint (`query2.finance.yahoo.com/v8/finance/chart/...`). Has custom logic to pick pre-market/regular/post-market price and compute change % differently for ETFs (`TQQQ`/`SOXL`) vs. indices, plus a secondary "spot" price fetch for futures symbols (e.g. `ES=F` → `^GSPC`).
- `api/etfs` (`dynamic = 'force-dynamic'`) — contains a large hardcoded `masterPool` object (~90 Korean- and US-listed ETFs) with static metadata (size/style weights, dividend yield, CAGR by period) baked into the source, then fetches a live price for each symbol from the same Yahoo Finance chart endpoint and merges it in. Sector weightings are the exception to "hardcoded": they're fetched live per-symbol via the `yahoo-finance2` package (`quoteSummary` → `topHoldings.sectorWeightings`), wrapped in `unstable_cache` with a 7-day revalidate (`SECTOR_CACHE_SECONDS`), and fall back to the hardcoded `sectors` value in `masterPool` when Yahoo has no data for that symbol (common for `.KS`-listed ETFs) — each item's `xray.sectorsSource` is `'live'` or `'fallback'` accordingly. Also accepts `?extra=SYMBOL1,SYMBOL2` (comma-separated, validated against `/^[0-9A-Za-z.\-^]{1,15}$/`, capped at 30) for tickers the user added manually on `/archive` that aren't in `masterPool`: each is normalized (a bare 6-character alphanumeric code gets `.KS` appended, assuming KRX), then given live price (reusing `fetchYahooPrice`), live sector weightings (`fetchLiveSectors`), and live name/dividend-yield/1y-3y-5y-10y-CAGR (`fetchExtraMetrics`, also `unstable_cache`d 7 days — computes CAGR by finding the closest historical weekly candle to each lookback target, same technique as `api/sector-performance`). These custom items are appended to the returned `pool` with `xray.isCustom: true` and empty `sizes`/`styles` (no reliable free source for Morningstar-style size/style-box data), and `code` is whatever raw string the user typed (not necessarily matching `symbol`).
- `api/sector-performance` — independent of `api/etfs`; computes 1-year return and a long-term (up to 10y, shorter for younger funds) annualized CAGR for the 11 GICS sector SPDR ETFs (XLK, XLF, XLV, XLY, XLP, XLI, XLE, XLU, XLB, XLRE, XLC) from `yahoo-finance2`'s `chart()` module (weekly candles). Entire result is wrapped in `unstable_cache` with a 7-day revalidate. Consumed lazily by `/archive`'s 리밸런싱 tab (fetched only once that tab is opened, not on every `/archive` page load).
- `api/journal-quotes` (`dynamic = 'force-dynamic'`) — batch current-price lookup for arbitrary tickers via `yahoo-finance2`'s `quote()` (accepts `?symbols=NVDA,AAPL,005930.KS`, dedupes/uppercases them, returns `{ quotes: { SYMBOL: { price, currency } } }`). No caching (real-time, matching the rest of the price-facing UI); invalid/unknown symbols are simply omitted from the response rather than erroring. Consumed by `/journal`'s 매매일지 tab.
- `api/weekly-data` (`dynamic = 'force-dynamic'`) — for the 3 hardcoded ticker groups (indices, sectors, top S&P500 companies), fetches ~400 days of daily candles per symbol via `yahoo-finance2`'s `chart()` and computes 기준가, 52-week-high drawdown %, week-to-date %, month-to-date %, and trailing 1/3/6/12-month % — all from historical closes, no third-party "return" fields. The whole computation is wrapped in `unstable_cache` tagged `'weekly-data'` with an 8-day fallback `revalidate` (a safety net, not the primary refresh mechanism). Consumed by `/journal`'s 주간데이터 tab.
- `api/cron/weekly-data` — not user-facing; requires an `Authorization: Bearer $CRON_SECRET` header (Vercel auto-injects this for its own Cron requests, so no manual env var setup is needed in production) and calls `revalidateTag('weekly-data')` to force `api/weekly-data` to refetch on the next request. Triggered every Saturday by the `crons` entry in `vercel.json` (`0 0 * * 6`, UTC — i.e. Saturday ~9am KST). Vercel Cron only runs once deployed; it does nothing when running locally via `npm run dev`.

### Client-side persistence

`/archive` persists user portfolio state directly to `localStorage` under `kijay_tab_configurations` (tab → holdings/weights) and `kijay_etf_counts_v2` (share quantities). `/journal` persists trade-journal entries under `kijay_trade_journal`. There is no backend/database, so all of this state is per-browser only — it does not sync across devices and is not visible to other visitors of the site.
